# Service.Center — Phase-wise Build Prompt

Domain: **Service.Center** (the generic phrase "service center").
Use this document as the master prompt for any developer or AI agent extending the site. Each phase is a self-contained prompt; run them in order. Phases 0–4 are already implemented in this repository; 5–9 are the growth roadmap.

---

## The idea (decided)

**Service.Center is the cross-category "Find · Compare · Fix" hub for repairs and service.**
One site that lets a person with a broken phone, laptop, TV, fridge, car or furnace:

1. **Find** authorized and independent service centers (directory + official brand locators),
2. **Compare** what the job should cost (fair-price estimator, 30+ benchmarks, region-adjusted),
3. **Get up to 3 free quotes** from vetted local centers (the lead-gen engine), or
4. **Fix it themselves** with guides and videos.

Why this wins over alternatives (single-brand support clone, pure directory, pure blog):

| Option | Traffic potential | Revenue/visit | Trademark risk | Verdict |
|---|---|---|---|---|
| Brand-specific "X service center" pages | High | Low (ads only) | **High** — implies affiliation | Reject |
| Pure Yelp-style directory | Medium | Low–medium | Low | Too thin, needs supply |
| Pure repair blog | Medium | Low ($5–15 RPM) | Low | Slow, ad-only |
| **Cross-category hub with lead-gen + estimator + guides** | High (SEO on "X repair cost", "X service center near me", DIY) | **High** — leads $12–65 each on top of ads | Low (generic use, disclosed) | **Build** |

Revenue stack (ranked by expected $ per 1,000 visits):

1. **Repair leads** sold to local shops — $12–65/lead; at a 2–4 % request rate that is $240–$2,600 per 1,000 visitors.
2. **Google AdSense** on guides/cost pages — home-services and auto repair are high-CPC niches (typical RPM $15–40).
3. **Featured listings** — $149/mo per city per partner; recurring.
4. **Sponsorships** — category, estimator, contest and sponsored guides ($250–$899+).
5. **Affiliate** — parts, tools, extended warranties (Amazon, iFixit, eBay).
6. **YouTube** — embedded videos plus own channel ad revenue.
7. **Donations / memberships** — Buy Me a Coffee, Ko-fi, PayPal, Patreon, GitHub Sponsors, Stripe.

Trademark position: "service center" is a descriptive generic term. The site uses it only descriptively, never claims exclusivity, never implies affiliation with any brand or any business named "X Service Center", and carries a full disclosure in the footer of every page and on `/disclaimer/`. Brand names are used under nominative fair use for identification only, with links to official support.

## Phase 0 — Constraints (apply to every phase)

```
You are building Service.Center, a static website hosted on GitHub Pages (free plan).
Hard rules:
- Pure static: HTML/CSS/JS + JSON data. No server. Forms use a form relay (FormSubmit/Formspree/Web3Forms).
- Generated by build.py from src/pages_*.py. Never hand-edit generated HTML; edit the generator.
- Top of EVERY page: a banner reading "Contact, if you are interested in this website / domain name /
  Sponsorship / Advertisement / Partnership" linking to https://web.works/contact.
- ONE contact email for everything, stored ONLY base64-encoded in assets/js/config.js (contactKey).
  Never render it as text, never put it in HTML, markdown, README, sitemap or commit messages.
  Contact links use data-contact and decode on click; forms post via the relay.
- Relative asset paths (data-root) so the site works at /<repo>/ and at the root domain.
- Trademark disclosure in the footer of every page; nominative use of brands only.
- Mobile-first, accessible (skip link, labels, focus rings), dark-mode aware, Lighthouse ≥ 90.
- Every page has: title, meta description, canonical, OG tags, sitemap entry.
- AdSense slots (.ad-slot) render only when config.adsenseClient is set; keep ad-to-content ratio policy-safe.
```

## Phase 2 — Core money pages (done)

```
1. Home: hero with category+keyword search, six category tiles, 3-step how-it-works, embedded
   quote wizard + sidebar ad, cost teaser cards, guides, testimonials, B2B trio, newsletter.
2. /get-quote/: dedicated 5-step lead wizard (category → service type → urgency → details →
   contact), consent checkbox, trust row, FAQ, partner sidebar. Prefill via ?cat=.
3. /find/: client-side directory over data/centers.json with search, category, city, sort;
   Featured/Authorized/Demo badges; "Get quote" and "Claim listing" per card.
4. /costs/: estimator over data/costs.json with region multiplier and DIY verdict.
5. /categories/<slug>/ ×6: hero, job chips → quote, embedded estimator, repair-or-replace rule,
   guides, videos.
6. /brands/: official manufacturer support & authorized-service locator links (real URLs).
```

## Phase 5 — Go-live configuration (owner, ~1 hour)

```
1. config.js: set adsenseClient + adSlots; ads.txt publisher id; ga4 or plausibleDomain.
2. Submit one test form → activate FormSubmit → replace formEndpoint with the hashed endpoint.
3. Set support.* URLs (BMAC/Ko-fi/PayPal/Patreon/GitHub Sponsors/Stripe link).
4. youtube.channelId + byCategory playlists; social handles.
5. Custom domain: add CNAME file "service.center", set DNS A records to GitHub Pages IPs
   (185.199.108–111.153) + CNAME www → webworksa1.github.io; enable "Enforce HTTPS".
6. Search Console + Bing Webmaster: submit sitemap.xml.
```

## Phase 6 — Supply & lead routing (weeks 1–4)

```
Replace demo listings in data/centers.json with real, verified centers (start with 3 cities ×
6 categories). Add a Google Sheet / Airtable as the lead inbox (relay → Zapier/Make → sheet →
partner email/SMS). Add lead pricing table and invoice flow (Stripe Payment Links per plan).
Add per-city landing pages: /<city>/<category>/ generated from a cities list for local SEO.
```

## Phase 7 — SEO content engine (months 1–6)

```
Generate 200+ programmatic pages: "<job> cost", "<brand> <device> repair near me",
"<symptom> — causes & fixes". Each page: estimator embed, quote CTA, 2 guides, 1 video, FAQ schema.
Publish 2 tested guides/week + 1 video/week. Build the newsletter list; monthly contest emails.
```

## Phase 8 — Interactive tools (months 3–9)

```
AI triage assistant ("describe the fault → likely cause + price range + DIY/pro verdict") using a
serverless function (Cloudflare Workers/Vercel Edge) so hosting stays free-tier.
Warranty checker (age + brand → likely coverage), repair-vs-replace calculator, price-report
crowdsourcing that updates costs.json via PR.
```

## Phase 9 — Marketplace expansion (months 6–18)

```
Partner dashboard (Supabase auth), instant-book fixed-price jobs for common repairs, reviews
with verified-lead badge, memberships ("Service.Center Plus": ad-free + priority quotes),
multi-country/currency (CA, UK, AU, IN), white-label city franchises.
```

## Acceptance checklist (run before each deploy)

- `python3 build.py` builds without error; crawl reports 0 broken links.
- `grep -r "<the address>"` across the repo returns nothing.
- Owner banner present on every page; disclosure in every footer.
- Lighthouse mobile ≥ 90 performance/accessibility/SEO.
- Forms submit (relay) and fall back to the mail client when the relay fails.
